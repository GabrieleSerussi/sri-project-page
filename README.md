# Step-Wise Refusal Dynamics: project page

Static GitHub Pages site for *Step-Wise Refusal Dynamics in Autoregressive and Diffusion Language Models* (arXiv:2602.02600), designed in the visual language of [Decart Research](https://research.decart.ai/).

```
sri-page/
├── index.html            # Decart Research version (all copy lives here)
├── classic.html          # traditional project-page version, generated by make_classic.py
├── make_classic.py       # regenerates classic.html from index.html
├── css/style.css         # Decart design tokens, components, phone layout
├── css/hero.css          # styles specific to the interactive cover
├── css/theme-classic.css # overrides for the classic version (fonts, colours, nav, footer)
├── js/main.js            # cover animation, charts, explorer, rail, copy and share
├── assets/
│   ├── data/sri-real.json   # trajectories digitized from Figures 2 and 12 and Figure 1/11 snapshots (reference data, not used by the page)
│   ├── fonts/            # Roobert and Season, the files research.decart.ai serves
│   ├── img/              # Decart logos, favicon, paper textures, Chaim Baskin photo, lab logos
│   └── figures/          # Figures extracted from the PDF at print resolution
├── colab/
│   ├── sri_playground.ipynb  # Colab notebook: type a prompt, watch its SRI signal
│   └── README.md
└── .nojekyll             # tells GitHub Pages to serve files as-is
```

## Two versions

Open `index.html` for the Decart Research version and `classic.html` for the traditional version. On the local preview they are http://localhost:8765/ and http://localhost:8765/classic.html. `sri-page-decart.zip` and `sri-page-classic.zip` in the parent folder are ready-to-deploy copies (in the classic zip, `classic.html` is already renamed to `index.html`).

- `index.html` is the Decart Research version (Roobert and Season, paper texture, Decart nav and footer, navy banner).
- `classic.html` is a traditional project-page version of the same content: centered title block with the cover beneath it, Inter and Source Serif 4 from Google Fonts, white background, a plain nav with the paper's short name, light panels instead of the navy and blue backdrops, and a simple footer. Decart appears as an affiliation and in the "Affiliations and acknowledgements" box.
- `classic.html` is generated from `index.html` by `make_classic.py` (it swaps the head, the nav wordmark, the banner eyebrow and the footer, and links `css/theme-classic.css`). After editing `index.html`, run `python3 make_classic.py` so both stay in sync. To publish only the classic version, rename `classic.html` to `index.html` in the repository, or link to `classic.html` directly.

## Publish on GitHub Pages

### With a custom domain (recommended)

1. Create a public repository on GitHub (for example `sri-project-page`). Public is required for the Colab link, which opens the notebook from GitHub.
2. Choose the version: unzip `sri-page-classic.zip` (classic) or `sri-page-decart.zip` (Decart); or work in this folder directly.
3. Fill in the deployment values and rebuild: `python3 configure.py --url https://sri.example.org/ --repo USER/sri-project-page`. This also writes `CNAME` with your host.
4. Push the folder contents to the `main` branch:
   ```bash
   git init && git add -A && git commit -m "Project page"
   git branch -M main
   git remote add origin git@github.com:USER/sri-project-page.git
   git push -u origin main
   ```
5. Repository Settings, Pages: Source "Deploy from a branch", branch `main`, folder `/ (root)`. The site is live at `https://USER.github.io/sri-project-page/` within a minute.
6. DNS, at the provider that manages your domain:
   - for a subdomain such as `sri.example.org` (also `sri.decart.ai`, which Decart's IT would add): a `CNAME` record from that host to `USER.github.io`;
   - for an apex domain such as `example.org`: `A` records to 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153 and `AAAA` records to 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153.
7. Repository Settings, Pages, Custom domain: enter the host, save, wait for the DNS check to pass, then tick "Enforce HTTPS". GitHub issues the certificate automatically.
8. Reload the domain: the Colab button opens the notebook from the repository and link previews use the cover image.

### Without a custom domain

1. Create a repository (for a `https://<org>.github.io/<repo>/` URL) or `<org>.github.io` (for the root URL).
2. Copy the contents of this folder to the repository root and push:
   ```bash
   cd sri-page
   git init && git add -A && git commit -m "Project page"
   git branch -M main
   git remote add origin git@github.com:<org>/<repo>.git
   git push -u origin main
   ```
3. In the repository: Settings, Pages, Build and deployment, Source: Deploy from a branch, `main` / `(root)`.
4. Open the Pages URL after a minute.

All paths are relative, so the site works from the repository root or from a sub-path.

## Before you publish

- **Run `configure.py` once you know the repository and the domain.** `python3 configure.py --url https://your.domain/ --repo USER/REPO` writes the absolute `og:image`, `og:url` and canonical URL, the Colab links in both pages, the links inside the notebook and `colab/README.md`, a `CNAME` file for a custom domain, and rebuilds `classic.html` and the two zips. Nothing else on this list needs manual editing after that.
- **Colab link (before configure.py runs).** The "Open in Colab" button and the "Colab demo" quick link resolve themselves at runtime: on a GitHub Pages host (`USER.github.io/REPO/` or `USER.github.io/`) the script builds `https://colab.research.google.com/github/USER/REPO/blob/main/colab/sri_playground.ipynb`, so the button works as soon as the site is published from the `main` branch of a public repository. On any other host (for example the local preview) the button downloads the notebook file instead and its tooltip says how to upload it to Colab. If you publish from another branch or a custom domain, edit the URL in `js/main.js` (section 8) and in `colab/README.md`, and replace `https://USER.github.io/REPO/` in the notebook's first cell. See `colab/README.md` for what the notebook does, its hardware needs and how it was tested (CPU smoke test with a 0.5B model; the GPU paths and the gated models were not run).
- **Affiliation.** Chaim Baskin is listed with Ben-Gurion University (superscript 2) and "Decart.ai, Israel" (superscript 4). The paper PDF lists only the university affiliation.
- **`og:image`.** Replace the relative path in the `<meta property="og:image">` tag with the absolute URL of the deployed site so link previews work.
- **Fonts.** Roobert and Season (Decart version) are self-hosted in `assets/fonts/`; the licence was confirmed on 2 September 2026. The classic version loads Inter and Source Serif 4 from Google Fonts.
- **Author links.** Eliron Rahimi (OpenReview), Rom Himelstein and Amit LeVi (Google Scholar), Avi Mendelson (Technion page), Chaim Baskin (BGU page). Elad Hirshel has no link because no personal page was found.

## Where the facts come from

- Every number on the page is taken from the paper's tables and figures. Chart data lives at the top of each block in `js/main.js` (`hrr`, `delta`, `gap`, `ablation`, `defenses`); the explorer notes are in `INFO`.
- The cover is a schematic of the mechanism (Sections 2.2 and 3, Figures 1, 2 and 12): the token sequences and the SRI curves are hand-authored in `js/main.js` and the caption says so. Append `?mode=ar` to the URL to open the autoregressive tab directly. Real trajectories digitized from Figure 2 (Qwen-2.5) and the LLaDA panel of Figure 12, plus the token snapshots of Figures 1 and 11, are kept in `assets/data/sri-real.json` for anyone who wants measured data.
- BibTeX is the official arXiv export. Emails: elironrahimi@campus.technion.ac.il (corresponding author, from the paper) and chaimbaskin@bgu.ac.il (from his BGU homepage).

## Editing notes

- Page structure: header with the interactive cover, a three-beat summary and four stat cards, then five acts (`#recovery`, `#sampler`, `#sri`, `#guard`, `#build`), the Discussion quote, BibTeX and contacts, and the Decart banner. The quick-links rail and the nav point at these ids.
- Design tokens (colours, spacing, type) are the `:root` block at the top of `css/style.css`, mirrored from Decart's stylesheet. Phone rules live in the `@media (max-width: 900px)` and `(max-width: 560px)` blocks. Two small diagram components (`.flow` steps with arrows, `.tokrow-block` token rows) live at the end of the file.
- Append `?static=1` to the URL to disable the reveal-on-scroll animation (useful for screenshots and print).
- House style for the copy: complete calm sentences, no em or en dashes, ranges written as "48 to 62%", every claim traceable to the paper.
